## 1. 审查结论概览

本次审查指出的核心事项包括：
- **1 个阻塞级 Bug (P0)**：在 `exec_fused_tail_and_head` 中，跨层融合列表的边界拷贝判定过宽，导致 `Head(L_next)` 的 `CLOSURE` relay 在 `tail(L_cur)` 刷新时被过早触发并拷出脏数据。
- **1 个待确认项（已核实确认）**：`olmoe_hi_baseline.txt` 基准文本改写完全是 deliberate 的——源于测试套件解耦（切换至生产 Release 产物 `StreamMoE` + 上下文 `-c` 双端协商收敛至 2048），已通过全量 12 拓扑回归验证。
- **6 条高价值改进建议**：
  1. `bucket_upload_leaf` 中推进 `stage_used` 缺少与 stage buffer 上限的越界断言保护。
  2. `t.acc` in-place 直接别名 `moe_out` 时缺少 `nb[0]==4 && nb[1]==d_out*4` 连续性步长校验。
  3. `H2D skip-sync` 的后端并发语义（已对照本地源码核实：Vulkan 未实现 `set_tensor_async`，底层自动退化为同步等待，无竞争风险，但后续跨后端需保持警惕）。
  4. 上下文协商 `min(modelCtx, taskCtx)` 导致大 prefill 任务（如 `prefill10000`）被截断（8192 < 10000）。
  5. `run_bench.js` 缺少 `--flavors` 命令行解析支持。
  6. 子单元小优化：`flush_segment` 中指定设备找不到 backend 时应显式报错、`run_baseline.bat` 步骤分母编号规整、`smoke_cli.js` 招呼词正则放宽。

## 3. 架构原理解析

### 3.1 跨层融合 Relay 时序提前成因 (P0-1)
在 `exec_fused_tail_and_head` 中，将 `tail(L_cur)` 与 `head(L_next)` 拼接后，由于 `topo_segment_execute` 在设备切换触发 `run_boundary_copies(cur_dev)` 时只根据 `src_key == cur_dev` 匹配，导致在执行第 L 层的 Tail 节点时，误将属于第 L+1 层 Head 且尚未计算的源张量拷贝出去。同时因 `executed_relays` 指针去重，导致后续 Head 算完后无法再次拷贝，从而使下游 closure 消费了未初始化的陈旧数据。
解决方案是在判定中增加遍历游标门控：若遍历尚未到达 `tail_size`，禁止触发任何 `r.layer == layer_head` 的 relay。

### 3.2 Scratch Arena 生命周期与单层单断架构
排查再次确证：`layout_arena` 中的非 carry scratch 区域在每层均复用 offset 0 起始的物理显存。若强行将计算图合并跨越层边界到 `Head(L+1)`，必然导致层内临时张量地址重叠与乱码。同层融合 `[MoE(L) + Tail(L)]` 是兼顾完全显存安全与硬件零冗余调度的最优终态形态。
